# agentic_workflows — TL;DR анализа

Redaction legend: Project A, Project B, and Project C are anonymized labels; the mapping is intentionally not recorded.

Полная версия: `2026-09-16-comparative-analysis.ru.md`. Дата: 2026-09-16.

## Что это

Спецификация AI-SDLC целиком на markdown (≈76 000 слов, 38 workflow, 14 rules), деплоится
в Claude Code / Codex / Windsurf. Пайплайн: спека → Discovery → Execution (TDD на каждую
подзадачу) → Validation (контракт, ревью, fix-задачи). Всё состояние — на диске в `.ai/`.

## Сильные стороны

- **Принудительный TDD**: RED наблюдается, набор тестов замораживается, `pinned` для
  рефакторинга, `none` только с обоснованием.
- **Независимый Validator** без контекста Implementer; Арбитр отвечает только с цитатой.
- **Класс A/B эскалация + batch-gate**: один запланированный стоп на задачу, до первой ветки.
- **Git-модель под ревьюера**: stacked-ветки, `test:`+`feat:` коммиты, `/restack` после
  любого merge, safety rails, ноль следов пайплайна в репозитории.
- **Resume-контракт**, quick-tier и `/bugfix` для мелких правок, multi-repo umbrella.
- **Телеметрия + `/retro`** — единственный фреймворк, который измеряет сам себя.
- 534 контрактные проверки и внешний аудит собственных инструкций.

## Слабые стороны

- **Нет runtime** — 123 точки остановки и все запреты живут в тексте; логи показывают
  нарушения (шаги залогированы задним числом с duration 0, статусы вне вокабуляра).
- **Дорого и долго**: spec-run 21–26 ч, одна подзадача до 15 ч, `pd-select-model` 3 ч
  (web-поиск каталога моделей каждый запуск), агент убит по spend limit. Бюджетов нет.
- **Огромный контекст**: десятки тысяч токенов инструкций до первого файла кода.
- **Строго последовательно** — параллельность запрещена из-за одного файла состояния.
- **127 перекрёстных ссылок**, grep-валидация, дублирование справочников в 4 местах.
- **Источник истины не под git.**
- **Python/FastAPI/GCP-центричность**; другие стеки — переписывать principles.
- Высокий порог входа, нет `examples/`; Windsurf/Codex не исполняют субагентную модель.

## Кому подходит

**Да:** долгоживущие backend/infra-проекты (Python, Terraform), 1–3 инженера + AI, ревью
через PR, multi-repo, legacy с онбордингом, аудируемые домены, задачи на 3–8 подзадач.
**С оговорками:** другие стеки, фронтенд, команды без владельца `.ai/`.
**Нет:** прототипы, однострочные правки вне `/bugfix`, ML-ноутбуки, жёсткие лимиты
бюджета/времени, работа только в Windsurf/Codex с `/spec-run`.

## Что улучшить (по приоритету)

1. Положить репозиторий под git, писать `contract_version:` в `state.md`.
2. Валидировать enum-поля в `log-step.sh`; логировать через hooks, а не через промпт.
3. Кэшировать каталог моделей (TTL), урезать `pd-select-model`.
4. Бюджеты токенов/времени на подзадачу; `cost`/`tokens` в run-log.
5. Перенести запреты (`git add -A`, push в main, правка RED-тестов) в hooks/permissions.
6. State-tool CLI вместо ручного редактирования markdown-блоков.
7. Расслоить правила на contract (always-on) и rationale (по требованию); цель ≤15k токенов на шаг.
8. Golden-run тесты workflow в headless-режиме перед `sync.sh`.
9. Генерировать справочные таблицы из front-matter вместо 4 ручных копий.
10. Параллельность независимых подзадач через worktrees (после п. 6).
11. Стековые профили principles (TS, Go, React, Terraform).
12. Given/When/Then или EARS для AC; трассировка AC → тест → коммит в теле PR.
13. Честная матрица сред: Claude Code — первичная, Codex/Windsurf — ограниченные.
14. `examples/` с полным прогоном и «первые 15 минут» в README.

**Главная мысль:** не добавлять правила, а переводить уже написанные в исполняемую
форму — тогда станет безопасно сокращать контекст и включать параллельность.
