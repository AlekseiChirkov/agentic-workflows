# architecture.md — current snapshot of the system's architecture

## Purpose
Describes the system as it exists now: modules, components, data flow,
external dependencies. The agent updates this file when an architectural
decision (recorded under `adr/`) materially changes the snapshot. Answers
"what is the shape of this system today?" Changes infrequently — only on
real structural shifts.

## Structure

## Overview
One paragraph: what the system does and how the major parts fit together.

## Components
One subsection per major component: responsibility, key interfaces, dependencies.

## Data Flow
How data moves through the system: ingress, processing, persistence, egress.

## External Dependencies
Third-party services, libraries, infrastructure the system relies on.
